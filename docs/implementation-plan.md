# 架构与实现边界

本文件承接 2026-11-13 确认的实施范围，2026-11-14 按现有工程重整。它说明职责和设计决定；实际验证状态见 [进度记录](progress.md)。

## 产品范围

主应用提供中文北京中轴线图志：三维城市总览、二维地图、遗产点说明、北中南三个章节入口和独立样例路由。视觉以午后至黄昏的暖色场景为基调，保留南北轴向、代表性建筑、道路与水系关系。

模型是有资料依据的导览表达。显示包络、缺省高度、树位、院落补线与视觉对齐包含推估，不能称为遗产测绘或某一历史时期的精确复原。正式章节的内容与视觉由章节作者维护。

## 路由与交互

| hash | 用途 |
| --- | --- |
| `#/` | 城市总览 |
| `#/site/{id}` | 在总览中选择地标并打开详情 |
| `#/chapter/north`、`#/chapter/central`、`#/chapter/south` | 对应章节的 iframe 框架 |
| `#/sample` | 样例展示状态 |

三维地图支持拖动平移、Shift + 拖动旋转和滚轮缩放；二维地图支持中键拖动、滚轮缩放与地标点选。WebGL 初始化失败时提供二维显示。章节覆盖期间三维渲染暂停；返回与独立打开由父应用保留。

## 关键技术决定

1. **静态主应用**：React 管理界面，Three.js 管理三维场景，Vite 生成静态产物；不设置后端、账号、数据库或运行时 AI。
2. **共享数据与布局**：二维与三维尽量共用遗产登记、投影和专用布局，减少各自维护一份位置、墙线或桥位的偏差。
3. **本地地理快照**：地图原始 WGS84 与 POI 的 GCJ-02 口径分开保留，在显示管线中转换；具体流程见 [研究方法](research/methodology.md)。
4. **独立章节边界**：默认通过 iframe URL 集成，不要求章节与父应用使用相同框架，也不共享 DOM、CSS 或运行时状态。
5. **资源与降级**：使用本地资源或系统字体；文字入口、二维显示与独立章节打开为不同能力设备提供浏览路径。
6. **测试资源限制**：Three.js 模型检查使用单 worker 独立进程，避免按 CPU 数放大内存需求。约束和本轮禁跑说明见 [开发指南](development.md)。
