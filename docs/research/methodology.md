## 1. 来源的作用与优先级

| 证据类型 | 主要来源 | 能支持的结论 | 不宜据此断言 |
| --- | --- | --- | --- |
| 官方文化与遗产说明 | UNESCO、北京市政府、北京市文物局、故宫博物院、中国国家博物馆 | 页面明确记载的年代、名称、功能、形制与数字 | 所有附属建筑已穷尽，或全部模型尺寸都得到认证 |
| 设计方资料 | gmp国家博物馆项目页 | 历史立面保留、新旧体量和柱廊关系 | 当前现场每个构件均与某张设计图完全一致 |
| 地图与POI | OSM、高德 | 锚点、道路/河道、建筑外轮廓、映射属性 | 遗产法定保护边界、完整测绘、POI就是建筑几何中心 |
| 照片、航拍与官方图文展 | 文博机构、首都图书馆、Commons文件页 | 轮廓、相对体量、材料色彩、可见门窗和侧廊层次 | 单张透视照片给出准确长宽高，或不可见背面已得到验证 |
| 模型与测试结果 | 本地代码、回归测试、自制截图 | 这些资料如何被实现，是否发生穿插、重复或错位 | 历史事实本身成立 |

来源登记区分“官方原始资料”“机构资料转载”“报道/专家介绍”“视觉参考”和“数据服务”。转载时保留发布者和原始机构的区别；图片按文件页逐图确认作者及许可。

## 2. 地图数据的取得与保留

早期尝试通过Overpass及OSM接口获取几何时遇到代理拒绝、超时和HTTP错误，暂时采用手工概化的 `src/data/context.ts`。后续压缩POST查询成功，取得真实OSM建筑、道路、公园及水系数据。**“曾经获取失败”与“当前仍没有数据”是两个不同结论。** [早期笔记](sources.md) 保留了前一阶段经过；当前数据状态见 [building-footprints.md](building-footprints.md)。

本地文件的角色：

| 文件 | 坐标 / 内容 | 角色 |

## 3. 坐标转换与共同轴向

高德锚点使用GCJ-02；OSM原始数据为WGS84。浏览器侧通过 `src/scene/geodata.ts` 的转换函数统一到GCJ-02，再由 `src/scene/geo.ts` 投影到场景。场景每一单位代表约10米的平面尺度；这是本项目的局部近似，不是测绘坐标系统。

投影先在原点 `[116.3975,39.9074]` 周围进行局部经纬换算，再以已复核午门—神武门方向作为展示平面的共同轴向。道路、水系、建筑、树木、拾取位置及二维地图使用同一变换。这样可以保持真实相对位置，又使主要宫城轴向便于阅读；不能通过分别“扶正”每一个地标来伪造严格共线。

仍需区分：

- **POI锚点**用于标签和浏览范围；可以位于入口或某一附属空间。
- **真实轮廓**来自地图中的建筑环；存在志愿绘制误差、缺漏和属性误标。
- **视觉包络**是用于模型辨识的宽深参数；不是保护红线或建筑面积。
- **照片补建**用于缺失部分的解释性形态；需要单独说明推估来源。

万宁桥是典型案例：高德POI位置保留作标签参考；实际桥体采用本地OSM way `561198196` 的桥梁道路段。该段明确带 `bridge=yes` 与 `bridge:name=万宁桥`，起终点为WGS84 `[116.3898859,39.9351679]`、`[116.3898988,39.9348597]`。模型中点及方向由这两个端点经相同转换求得，不能直接拿POI标签当桥心。

## 4. 从资料到模型的决策记录

每次关键修正至少应回答：

1. **观察到的问题**：例如天坛圆殿被画成通红的块体，或两座钟鼓楼用了同一屋顶。
2. **支持依据**：对应来源编号、照片可见特征、地图对象ID与使用日期。
3. **采用的解释**：例如祈年殿三重蓝色圆顶、钟楼灰砖石主体、鼓楼三重檐红色主体。
4. **保留的几何约束**：原建筑轮廓、河道孔洞、既有道路连接及院墙范围。
5. **验证及限制**：真实浏览器截图和测试能证明实现；推估的高度、花纹和缺省房屋仍需标记。

### 2026-11-14 · 城门楼层柱脚衔接

天安门、端门与永定门共用双层厅楼生成逻辑。首轮仅用垂直射线延长上层柱身，墙体、门窗和柱础却保留原位置，造成柱子脱离房身；该做法及其“修复完成”判断已撤回，首轮截图只保留作错误记录。

续修取消射线和柱体单独缩放，将上层完整木构房身由下檐标高起生成，高度为原有主体高度的0.90倍，墙身、门窗、梁架和柱子一起嵌入下层坡屋面；上檐及两层屋顶位置保持原值。0.90为原有0.58间隔加0.32上层高度的模型参数组合，不是实测楼层比例。回归同时检查柱子与房身高度一致、墙体四面及柱脚接入下屋面，避免只测柱脚接触就误判。共享函数也用于其他重檐厅楼，因此合并验证故宫、天坛、正阳门相关检查。没有更改地图数据、坐标系统或外部来源结论；照片条目仍沿用既有核验状态。六个正面/侧面视角见[图册续修](figures/README.md#2026-11-14--城门上层房身整体衔接续修)。

同日自然度续修：上层采用贴柱墙面，使墙窗与柱心所在平面衔接；此配置仅由共享重檐上层显式启用，默认房身继续生成开放柱廊。墙根收边以四周连续矩形环采样下层实际网格：由墙内0.012模型单位至墙外0.11单位分三圈，分别抬高0.055、0.030、0.006单位，以窄缓坡接回瓦面；这些都是视觉参数，不是实测尺寸。不存在屋面交点时不生成该收边，不补造高度。回归增加柱心与房身包络衔接、收边顶点始终贴随真实屋面及下层外廊保留检查。截图和限制见[自然衔接图册](figures/README.md#2026-11-14--城门柱墙与瓦面自然衔接)。

[逐地标证据表](evidence-matrix.md) 集中记录以上信息。`scene-references.md` 保留较细的建筑观察和历史工作笔记；新读者优先从中文总览及证据表进入。

### 2026-11-14 · 天安门外金水桥与端门比例续修

外金水桥此前的桥心直接取高德“外金水桥”POI。该标签点比本地OSM主水面约北10个场景单位，导致栏板落在河北岸；把桥简单南移又会牺牲逐桥与门洞的关系。现改为两层约束：桥的横向轴心来自天安门五券洞及东西侧门序列，跨水中心来自本地OSM外金水河水面的南北截面。二维和三维都读取同一个 `jinshuiLayout(context)` 结果。桥台在OSM中会导致水体断开时，程序只在轴线两侧各2个场景单位内寻找最近河段；若数据缺失或测试未加载地图，才退回旧参数作测试占位。

水面截面宽度可能不足一个场景单位。为避免总览时栏板完全不可见，显示层保留最小2.1场景单位的跨水长度，但中心不移动。这个放大是图集视觉解释，不能反过来成为河道宽度或桥长事实。五座主桥的桥面宽度不超过对应券洞宽，外侧两桥只显示跨河段。`JINSHUI-SWJ` 与 `JINSHUI-2019` 对两侧公生桥孔数的说法不同，因此本轮不绘制可被误读为“已核定三孔/单孔”的拱洞数量。

天安门城台高度改用 `TIAN-DPM` 的16.19米，总高仍由 `TIAN-VISIT` 的34.7米控制；因此城台上移后，需要相应压缩檐间与下层木构高度，而不是继续按原通用厅楼叠加。`TIAN-VISIT` 另有重建时期32米高叙述，保留为不同历史口径。

端门城台采用OSM包络，楼身采用 `DUAN-DPM` 的187尺×85.9尺记录，以约0.32米/尺换算。换算、城台高度、檐口与曲面仍未获测绘图，禁止把模型截图倒推为实测。永定门按 `YONG-DONGCHENG`、`YONG-REBUILD` 区分历史原貌与复建现状，用灰色城台和灰瓦绿剪边替代原通用红台黄瓦；两套尺寸没有取平均。具体数值、冲突和截图见[比例校核](gate-proportions-review-2026-11-14.md)。

## 5. 数字、名称冲突及缺失资料

不把不同来源数字简单取平均，也不把旧时形制和现存建筑混在一起。

| 例子 | 处理方式 |
| --- | --- |
| 皇穹宇OSM高度标签约19.02米，文物文章提出现存建筑约19.2米 | 标注来源与口径；数字差异不能用于宣称分米级精度 |
| 万宁桥镇水兽有四座/六座口径 | 登记差异；四座模型是选择性表达，不写成逐座现状清点 |
| 先农坛庆成宫尺寸、台阶数量存在不同说明 | 保留分歧；院落宽深与新增屋顶包络标为解释性布局 |
| 圜丘外壝附近OSM门名与位置不符 | 将命名属性与现场空间/文物形制交叉核对；保留原始数据，在显示解释层纠正，不篡改原始快照 |
| 缺少侧立面、背面或附属房屋资料 | 采用克制的通用细部或标为待补，不声称照片已覆盖全部方向 |

圜丘案例的对照记录：附近外壝东门way `43922668` 在捆绑数据中名为“泰元门”，但位置距坛心约83米；另一way `43925093` 对应更外围的泰元门。结合 `TEMPLE-MOUND` 关于内外壝均为六柱三门的说明，应把“属性标签”“相对位置”“门型”分别核查，不能仅按名称把外壝石门生成一间封闭红房。

## 6. 图片、纹理与可离线运行

参考照片用于观察与建模决策，不自动成为项目素材。当前建筑纹理主要为本地程序生成的砖、瓦、石材与色彩，未把所阅官方图文或Commons照片下载后混入运行时纹理包。借鉴外观与复制图片属于不同的素材使用情形，目录中保留两者区别。

本地 `/tmp/` 中的临时图片不能作为长期研究归档。本次仅把已有、自制的模型校核截图复制到 [figures/](figures/README.md)，附用途和中途状态说明；未将外部原照片复制进入仓库。最终比赛若直接展示外部照片，需补全对应文件的作者、来源页、许可/授权信息及必要署名。

地图运行读取本地数据，不依赖在线地图瓦片、CDN脚本、远程字体或运行时AI生成。研究链接需要联网访问，与浏览器运行时依赖是两回事。

## 2026-11-14 · 正阳门定位与尺寸的分离

本次没有变更投影、坐标系或OSM快照。`zhengyangLayout`继续从既有两个建筑way读取独立中心与方向；`zhengyangCityPlatform`则根据 `ZHENGYANG-FIRE-2020` 第2页设定显示包络，不把地图way的109.6×22.0m当成城台测量值。`zhengyangPlatformRing`用于二维图与三维底图，三维城台采用相同基底尺寸；各檐包络也由共享参数输出。OSM原始环不覆盖或修改，因此原始数据快照清单的哈希不需重算。
